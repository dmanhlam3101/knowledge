## 2. Bẫy và quyết định riêng

- **B1. Hai cột trạng thái.** `BRIEF.STATUS` = trạng thái **bàn giao** (1 / 3 / 4 / 5), `BRIEF.BRIEF_STATUS` = **đang thực hiện / đã đóng** (1 / 2). Web dùng chung hằng `BRIEF_STATUS.STATUS2` của nhóm bàn giao để so `briefStatus` (BIVM:1340, 2211) — chạy đúng chỉ vì cùng giá trị 2. Truy vấn danh sách mặc định lọc `STATUS IN (1, 3, 4, 5)` (BDAO:612-614) — đừng thêm giá trị mới cho `STATUS` mà không sửa các điều kiện này (BDAO:328, 368, 549, 766…). Dữ liệu: `BRIEF_STATUS` null = hồ sơ tạo trước 12/2020 (856 hồ sơ `STATUS = 1` + 44 hồ sơ 3/4/5) — điều kiện viết `BRIEF_STATUS = 1` (ví dụ 5 mức trạng thái xử lý, BDAO:737-741) bỏ sót nhóm này, còn điều kiện viết `≠ 2` (nút đóng — BIVM:2246-2252) thì coi nhóm này là đang thực hiện; 1 hồ sơ `STATUS = 2` (2025-09-25), 4 `STATUS = 0` (2017), 4 `STATUS` null (2025) không có đường ghi trên `kha_develop` (DB DEV `BRIEF` ngày 2026-10-01).
- **B1b. "LTHS" chính là vai trò `LT`.** Code gen-1 so theo id `SYS_ROLE_LTHS = 336956` (`C1:129`), CBDAO / kho so theo mã `'LT'` — DB DEV `SYS_ROLE` ngày 2026-10-01: 336956 = `LT` "Lưu trữ hồ sơ", **không có mã `LTHS`**. Vai trò hồ sơ tài chính là `QLHSTC` (337571), khác hẳn.
- **B2. Tiếp nhận đổi `CREATED_BY`.** Sau tiếp nhận, `CREATED_BY` = người nhận, `AUTHOR` = tên người nhận (BDAO:2448-2457). Mọi chỗ coi "người lập" là `CREATED_BY` thực chất là **chủ hiện tại**; người lập gốc chỉ còn ở `BRIEF_PROCESS` loại 1 và lịch sử bàn giao.
- **B3. `BRIEF_DOCUMENT` là bản chụp.** Metadata văn bản chép lúc gắn và không đồng bộ lại (NV-06 BR-19); nhưng danh sách file đọc trực tiếp từ văn bản gốc (BDDAO:309-410), và kiểm điều kiện đóng / nộp dùng `STATUS_NUMBER`, `STYPE_ID` của **bản chụp** (BDDAO:287-294). Hủy ban hành văn bản đi sẽ tự gỡ văn bản khỏi hồ sơ ở phía văn bản đi (`../van-ban/di/nghiep-vu.md`).
- **B4. Dự thảo gắn hồ sơ bằng chuỗi** `TEXT.BRIEF_ID` (id cách nhau dấu phẩy, tìm bằng `LIKE` — BDDAO:429-495; ghi ở `TextDAO.java:10803-10870`). Không có bảng liên kết.
- **B5. `BRIEF_DOCUMENT_MAP.DOCUMENT_TYPE` null = tab Văn bản liên quan** (dữ liệu trước `SQL/20250716_add_column_document_type_into_brief_document_map.sql`; DB DEV 10.777 dòng null). Mọi điều kiện theo tab phải tính cả null (BDDAO:104-117).
- **B6. `BRIEF_TYPE` lệch nghĩa** giữa nhãn web (`LBL:1585-1587`: 1 Sử dụng có điều kiện, 2 Công khai) và comment DB (`SQL/20250620_add_column_brief.sql:5`: 1 Công khai, 2 Sử dụng có điều kiện); bộ nhãn khác (`common_voffice_vi.properties:1562`, `zk-label.properties:1573`) lại ghi 1 = "Hạn chế". Logic code theo nhãn web: mượn chỉ cho 1, xem tự do khi 2 (`nghiep-vu.md` Q1). Đừng "sửa" comment hay nhãn trước khi có trả lời.
- **B7. Hai bảng mã thời hạn bảo quản.** Form dùng `TIME_STORAGE_TYPE` 0 có hạn / 1 vĩnh viễn (`AC:7538-7539, 7567-7572`); một map khác `STORAGE_TYPE_MAP` 1 vĩnh viễn / 2 có hạn (`AC:7694-7702`) cùng tồn tại.
- **B8. Mở màn chi tiết là ghi DB**: mỗi lần mở (kể cả người chỉ xem) tính lại và ghi `BRIEF.TOTAL_DOC`, `NUM_PAPER` (BIVM:476-478).
- **B9. Cờ mượn ngược tên.** Web gửi `isBorrowFull` = "có danh sách văn bản mượn" (`PopupBorrowBriefVM.java:71-74`), DAO nhận vào biến `isBorrowBrief`; `!isBorrowBrief` mới là **mượn cả hồ sơ** (BDAO:2722-2724).
- **B10. `STORAGES.ORG_ID` là chuỗi** dạng `,id,id,` (một kho dùng cho nhiều đơn vị), lọc bằng `LIKE '%,id,%'` (`StorageManagementDAO.java:126-128, 263-290`).
- **B11. Entity web `Shelve` → `@Table(name = "SHELVE")`** (`WEB/voffice/entity/Shelve.java:21`) nhưng DB chỉ có `SHELVES`; entity chỉ dùng để nhận JSON — đừng dùng nó để truy vấn JPA.
- **B12. Hàng đợi nộp hồ sơ là hợp đồng với hệ thống ngoài.** Giá trị `REQUEST_STATUS`, `IS_READY`, `STATUS` file, `NUMBER_RETRY`, `TRANSACTION_ID`, `DOC_CODE`, `OBJECT_TYPE`, `TYPE_FILE` do dịch vụ ngoài repo đọc / ghi (NV-15). Đổi nghĩa / thêm giá trị phải phối hợp phía phần mềm số hóa.
- **B13. Khối thao tác ẩn** `listDocumentDetailPanel` (`brief_info.zul:1678-1880`, `visible="false"`) chứa đóng dấu, chuyển văn bản, chuyển sang hồ sơ khác, yêu cầu bổ sung, mượn từ chi tiết — code VM vẫn còn và còn được tham chiếu (`nghiep-vu.md` Q9).
- **B14. Hai menu mượn khóa nhưng vẫn vào được** qua URL trong thông báo (`C1:1354-1355`). DB DEV `BRIEF_BORROW` ngày 2026-10-01: 577 yêu cầu / lượt cho mượn chưa xóa, phần lớn đến 2025, lần ghi cuối 2026-01-22 — dữ liệu mượn cũ còn nhiều, sửa luồng mượn phải giữ đúng các tổ hợp trạng thái hiện có (`nghiep-vu.md` NV-17).
- **B14b. File biên mục do tài khoản người dùng ghi.** DB DEV `CATALOGING_BRIEF_FILE` ngày 2026-10-01: khoảng 320 dòng do khoảng 19 người dùng tạo (2026-01-22 → 2026-04-10), 130 dòng không có người / ngày tạo — nhưng `kha_develop` không có đường ghi nào (`nghiep-vu.md` NV-15, Q7).
- **B15. Chặn tin**: loại tin 801–807 đã xóa khỏi `CONFIG_SMS_MODULE` (DB DEV) nhưng code vẫn ghi các mã này vào tin (NV-20); dòng chặn cũ vẫn được so khi gửi (`../lich-nhac-viec/nghiep-vu.md` mục 5.2).

## 4. Chỗ đừng đụng

- `BDAO.processBriefs` (:2395-2562) dùng chung cho bàn giao / tiếp nhận / từ chối, tham số `employeeId` / `receiverId` **đảo vị trí** theo loại (:2416-2422). Đổi chữ ký sẽ ảnh hưởng ProcessVM, ReceiveOrRejectVM, BUVM, ADLVM.
- `BSI.submitBrief` (:366-694) và `submitResult` (:1339-1392): hợp đồng với phần mềm số hóa (B12).
- `CATALOG_BRIEF.YEAR_NUMBER`: dữ liệu cũ gán 2025 (`SQL/20251225_…sql:8`); cây danh sách chỉ hiện 2 năm — đổi giới hạn năm ảnh hưởng mọi người dùng.
